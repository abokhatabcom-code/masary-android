# مرجع آمن للمرحلة التنفيذية 5 — التسجيل والبيانات الأكاديمية

هذا المجلد مستخرج يدويًا من نسخة مشروع منصة مساري وقاعدة بيانات أرفقهما مالك المشروع بتاريخ 2026-07-22. الغرض منه تزويد تطبيق Android وطبقة API بالمصدر الحقيقي لقواعد التسجيل، من دون رفع المشروع القديم كاملًا أو أي صفوف بيانات أو أسرار اتصال.

## إثبات المصدر

- حزمة المشروع: `masary.app 22_07_2026.zip`
- SHA-256 للحزمة: `23622a9df72bd05482dba15d015d92bdbd50b005707c60bf471a9219999fd9a0`
- نسخة قاعدة البيانات: `127_0_0_1.sql`
- SHA-256 لنسخة قاعدة البيانات: `509db905cc04b459e09d58cb4c1f6ad40493e1612cf1a145f23db1d08de63064`

لا تتضمن الملفات في هذا المجلد أي `INSERT` أو أسماء طلاب أو كلمات مرور أو رموز جلسات أو بيانات اتصال.

## المصدر القديم المثبت

التسجيل العام موجود فعليًا في `register.php`، والبيانات المرجعية العامة في `ajax/lookup.php`. لذلك الاستنتاج السابق داخل `docs/ISSUE_38_BACKEND_INVENTORY.md` بأن منصة مساري لا تحتوي تسجيلًا كان ناتجًا عن نقص نسخة `server-hostinger` المختصرة داخل المستودع، وليس وصفًا للمنصة الحالية.

## عقد التسجيل الحقيقي الحالي

### بيانات الحساب

- `full_name`: مطلوب وغير فارغ.
- `username`: مطلوب، من 3 إلى 24 محرفًا، ويسمح فقط بـ `A-Z`, `a-z`, `0-9`, `_`.
- `phone`: اختياري في التدفق الحالي.
- `email`: اختياري في التدفق الحالي.
- `password`: مطلوب، 6 محارف على الأقل.
- `password2`: يجب أن يطابق كلمة المرور.
- `gender`: مطلوب وقيمه الحالية `male` أو `female`.
- `student_personality`: اختياري، والقيم الظاهرة في الواجهة القديمة: `explorer`, `achiever`, `calm`.
- `privacy_accept`: مطلوب وقيمته `1`.

### البيانات الأكاديمية

- `city_id`: مطلوب، ويجب أن يشير إلى مدينة مفعلة.
- `requires_school`: يأتي من سجل المدينة، والقيمة الافتراضية عند غيابها هي `1`.
- `school_id`: مطلوب فقط عندما تكون المدينة ملزمة بمدرسة؛ وإلا يخزن `NULL`.
- المدرسة يجب أن تكون مفعلة، عامة للطلاب، وتتبع المدينة المختارة.
- `grade_id`: مطلوب، ويجب أن يكون الصف مفعّلًا وعامًا للطلاب.
- لا يوجد في التسجيل العام الحالي حقل قسم/شعبة أو اختيار منفصل للمنهج، ولذلك لا يجوز اختراعهما في API المرحلة الخامسة.

### تحديد المنهج

المنهج لا يختاره الطالب مباشرة. الأولوية المثبتة في `includes/curriculum_effective.php`:

1. منهج المدرسة عندما يوجد override مفعّل.
2. منهج المدينة المفعّل.
3. الملف الافتراضي الفعلي باسم `منهج عدن` للمدن القديمة غير المرتبطة.
4. استثناءات المواد على مستوى المدرسة تبقى داخل المنهج الفعّال نفسه ولا يجوز أن تسرّب نسخة من منهج آخر.

### إنشاء الحساب

يُنشأ صف في `app_users` بالقيم التالية:

- `role='student'`
- الحقول الشخصية والأكاديمية المتحققة أعلاه.
- `password_hash` باستخدام `password_hash(..., PASSWORD_DEFAULT)`.
- `student_code`: رقم عشوائي فريد من 6 أرقام.
- `is_active=1`.

التدفق القديم يسجل دخول الطالب مباشرة بعد الإنشاء. Android يجب أن يستخدم `SessionManager` ونظام التوكن الحالي، لا جلسة PHP الخاصة بالمتصفح.

## الفصل الصارم عن Push V2

`register.php` القديم يستدعي `push_v2_sources_on_student_created(...)` بعد إنشاء الطالب. هذا callback خاص بانتقال الويب/PWA القديم، ولا يُنقل إلى Android API ولا يُعدل من المرحلة الخامسة. نظام Android Notifications V1 سيُبنى مستقلًا في مرحلته المعتمدة.

## الاسترداد

لم يُعثر في النسخة القديمة على endpoint عام غير موثّق لاسترداد كلمة المرور أو OTP. لذلك لا يجوز إنشاء OTP شكلي. يبقى مسار الاسترداد داخل Android مسار دعم يدوي واضح إلى أن يُعتمد عقد خادم حقيقي وآمن للاسترداد.

## متطلبات API الآمنة المستخلصة

يُسمح ببناء adapter API جديد داخل `server-hostinger` اعتمادًا على القواعد أعلاه، بشرط:

- عدم النشر إلى Hostinger في هذه المرحلة.
- عدم تشغيل SQL أو تعديل بنية الإنتاج.
- التحقق الخادمي من كل العلاقات وعدم الثقة بمعرفات العميل.
- حماية الطلب المكرر. وبسبب عدم وجود UNIQUE على `username` في نسخة المخطط المرفقة، يجب استخدام قفل/معاملة خادمية مكافئة قبل الفحص والإدخال، مع إعادة فحص داخل النطاق المحمي.
- عدم تسجيل كلمات المرور أو التوكنات أو محتوى الطلب الحساس.
- تحديث OpenAPI والـfixtures والمدقق والاختبارات مع أي endpoints حقيقية تضاف.
