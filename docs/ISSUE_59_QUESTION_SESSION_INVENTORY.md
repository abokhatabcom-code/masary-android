# جرد المرحلة 13 — محرك جلسة الأسئلة وواجهات الحل

**المهمة:** GitHub Issue #59  
**الفرع الرسمي:** `official/phase-13-question-session`  
**فرع التنفيذ:** `phase-13-question-session-implementation`

## 1. نقطة البداية المؤكدة

المرحلة 12.6 أغلقت بعد نجاح Local-First/Offline واختبار حي على الجهاز. الموجود حاليًا:

- `api_activity_sessions` ينشئ جلسة نشاط آمنة بـ `public_session_id`.
- شاشة التجهيز `feature-activity-preparation` تمنع النقر المكرر وتعيد استخدام نفس الجلسة.
- الوجهة الحالية بعد بدء النشاط هي شاشة انتقالية `ActivitySessionReadyScreen` وليست واجهة حل.
- `core-local` يحتوي مسبقًا: `question_sessions` و`question_answers` و`pending_operations`.
- `recordQuestionAnswer` يحفظ الإجابة وتقدم الجلسة وعملية المزامنة داخل transaction واحدة.
- queue المرحلة 12.6 يحافظ على `operation_id` نفسه عبر retries.
- تغيرات النقاط/المستوى/القلوب المؤكدة يمكن تطبيقها عبر `ConfirmedStudentDelta`.

## 2. أنواع الأسئلة المثبتة في المنصة

- `choose` — الاختيار من متعدد
- `truefalse` — صح أو خطأ
- `connect` — التوصيل
- `fill` — الإكمال
- `speed` — السرعة
- `smart_review` — مراجعة أخطاء الطالب، ويظل غير متاح إذا لم يثبت مصدر أخطاء موحد.

المصادر التاريخية غير موحدة. لا يُعرض نوع سؤال أو عدد أو محتوى إذا لم يثبت مصدره وعلاقته بالمادة والجلسة.

## 3. حدود الأمان

- الطالب يؤخذ من Bearer session فقط.
- `session_id` لا يكفي وحده؛ يجب إثبات ملكية الجلسة للطالب الحالي.
- لا يرسل Android `student_id` كمصدر نطاق.
- الإجابة الصحيحة لا تُرسل للعميل لمجرد عرض السؤال.
- XP والنقاط والمستوى والقلوب لا تُحسب محليًا كمصدر حقيقة.
- لا يمكن لإجابة من جلسة أو طالب آخر أن تُكتب داخل الجلسة الحالية.
- كل mutation قابل للتكرار يستخدم مفتاحًا ثابتًا حتى لا تتكرر الإجابة بعد انقطاع الشبكة.

## 4. العقد المطلوب

### 4.1 تحميل حزمة الجلسة
يعيد فقط الجلسة المملوكة للطالب مع هوية النشاط والمادة والوحدة/الدرس، حالة الجلسة وصلاحيتها، قائمة أسئلة typed، موضع التقدم، `version` و`generated_at`. لا تُرسل مفاتيح الإجابة الصحيحة.

### 4.2 تسجيل إجابة
عملية idempotent مرتبطة بالطالب + الجلسة + السؤال. Android يحفظ الإجابة محليًا أولًا ويضيفها إلى queue من 12.6.

### 4.3 إنهاء الجلسة
عملية idempotent. النتيجة النهائية خادمية. أي تغير في XP/المستوى/النقاط/القلوب يعود كتغيير خادمي مؤكد ويطبق داخل المصدر المحلي المشترك.

## 5. سلوك Offline

- بعد تنزيل حزمة الجلسة تبقى محفوظة في Room.
- موضع السؤال والإجابات يبقيان بعد process death.
- الإجابة Offline لا تضيع.
- عند عودة الشبكة تُرسل العمليات المعلقة بنفس `operation_id`.
- لا تُكرر إجابة واحدة مرتين بسبب retry.
- لا يتم ادعاء صحة/خطأ أو منح مكافأة إذا كانت النتيجة تحتاج الخادم ولم تصل بعد.

## 6. واجهة Android

الوحدة الجديدة: `feature-question-session`.

الحالات الأساسية: تحميل محلي/شبكي، سؤال جارٍ، إجابة محلية بانتظار التأكيد، انتقال للسؤال التالي دون reload، استئناف، جلسة منتهية، اكتمال محلي بانتظار الخادم، نتيجة مؤكدة.

## 7. ترتيب التنفيذ

1. **13.1** عقد حزمة الجلسة + endpoint + fixture + اختبارات PHP.
2. **13.2** DTO/API + Repository + Room package persistence.
3. **13.3** محرك الشاشة وrenderers الخمسة.
4. **13.4** answer queue + endpoint idempotent.
5. **13.5** complete/result + `ConfirmedStudentDelta`.
6. **13.6** اختبارات Offline/process death/account isolation + APK قبول حي.

## 8. ما لا يدخل بدون مصدر مؤكد

- اختلاق جداول أو أعمدة أسئلة.
- إرسال الإجابات الصحيحة للعميل فقط لتسهيل Offline.
- منح XP أو مستوى أو قلب محليًا قبل تأكيد الخادم.
- جعل `smart_review` متاحًا دون سجل أخطاء مؤكد.
- إعادة كتابة نظام التجهيز الموجود؛ يتم البناء فوقه.
