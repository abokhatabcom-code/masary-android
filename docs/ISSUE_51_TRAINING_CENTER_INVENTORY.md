# جرد المرحلة الحادية عشرة — مركز تدريب المادة

**المهمة:** GitHub Issue #51  
**فرع التنفيذ:** `phase-11-subject-training-center-implementation`  
**نقطة الأساس:** `ecc066d2f82b0d68d6853dbce4a76e654522880e`  
**تاريخ الجرد:** 2026-08-03

## الملخص التنفيذي

المرحلة العاشرة أنشأت صفحة مادة حقيقية ووحدة `feature-subject`، لكنها أبقت إجراء مركز التدريب غير متاح صراحة. المرحلة الثامنة أنشأت شاشة تجهيز آمنة قبل النشاط، بعقد typed ومنع تكرار، وتدعم حاليًا الأنواع العامة: `unit_test`, `lesson_practice`, `review`, `smart_review`, `speed_test`.

مركز التدريب يحتاج عرض ست أدوات مستقرة: الاختيار، صح أو خطأ، التوصيل، الإكمال، السرعة، ومراجعة الأخطاء. فتح المركز يجب أن يبقى قراءة فقط؛ لا أسئلة ولا خصم ولا محاولة ولا جلسة. اختيار أداة متاحة يمر إلى شاشة التجهيز، ولا يبدأ النشاط مباشرة.

## 1. الوضع الحالي في Android

### 1.1 صفحة المادة

الملفات الأساسية:

- `feature-subject/.../StudentSubjectScreen.kt`
- `feature-subject/.../SubjectModels.kt`
- `feature-subject/.../NetworkSubjectRepository.kt`

يوجد زر «مركز تدريب المادة»، لكنه يعتمد على:

```kotlin
data.actions.trainingCenter.available
```

ويعيد الخادم حاليًا `available=false` لأن المرحلة الحادية عشرة لم تكن منفذة.

### 1.2 شاشة التجهيز

الملف:

`feature-activity-preparation/.../ActivityPreparationFeature.kt`

العقد الحالي يثبت:

- `subjectVersionId` موجب.
- `activityType` و`activityMode` و`source` من قوائم مسموحة.
- عدم بدء الجلسة قبل معاينة خادمية.
- منع النقر المكرر وحفظ مفتاح منع التكرار.

الأنواع الحالية لا تفرق بين الاختيار وصح/خطأ والتوصيل والإكمال؛ لذلك يجب تثبيت مفاتيح أدوات مستقرة في عقد مركز التدريب، ثم توسيع عقد التجهيز بطريقة متوافقة قبل الربط النهائي.

### 1.3 التنقل

الملف:

`feature-home/.../StudentDestinations.kt`

يوجد `SubjectDetails(subjectVersionId)` ولا توجد وجهة مستقلة لمركز التدريب. يلزم إضافة Route typed يحمل `subjectVersionId` فقط، ثم تمرير الأداة المختارة إلى `ActivityPreparationDestination` بقيم مسموحة ومتحقق منها.

## 2. مصادر الحقيقة في الخادم

### 2.1 ملكية المادة

الدالة المعتمدة في المرحلة العاشرة:

`api_student_subject_authorized_row(PDO $pdo, int $studentId, int $subjectVersionId)`

تعيد المادة فقط إذا كانت ضمن مواد الطالب المصادق. يجب إعادة استخدامها لمنع IDOR واستجابة موحدة للمادة غير المرتبطة.

### 2.2 بنية الأسئلة التاريخية

توجد في المنصة خمسة أنماط اختبار تاريخية:

- `choose`
- `truefalse`
- `connect`
- `fill`
- `speed`

لكن أسماء الجداول والأعمدة ليست موحدة بما يكفي للاعتماد المباشر دون فحص وقت التشغيل. القرار:

- استخدام whitelist للجداول والأعمدة المرشحة فقط.
- فحص schema وقت التشغيل.
- حساب التوفر بعدد مجمع، دون تحميل نص السؤال أو الخيارات أو الإجابة.
- عند غياب مصدر مؤكد لنوع ما، يعاد `available=false` وسبب واضح.

### 2.3 مراجعة الأخطاء

مراجعة الأخطاء يجب أن تعتمد على سجل أخطاء الطالب نفسه، لا على عدد الأسئلة العام. لم يُثبت بعد في عقد Android الحالي جدول موحد يحتوي الطالب والمادة ونوع السؤال بصورة مستقرة؛ لذلك يبدأ التنفيذ بجرد مرشحات schema، ويظل النوع غير متاح إذا لم يثبت المصدر.

### 2.4 شاشة التجهيز الحالية

الخادم في `_activity_preparation.php`:

- يثبت المادة من جلسة الطالب.
- لا يحمّل أسئلة.
- يعيد عدد الأسئلة والمدة كـ`null` عند غياب مصدر مؤكد.
- يدعم جلسات idempotent.

القرار: مركز التدريب لا يعيد استخدام preview ست مرات، لأن ذلك يسبب طلبات واستعلامات متكررة. يُنشأ endpoint ملخص واحد خاص بالمركز، ثم تستخدم شاشة التجهيز فقط بعد اختيار الأداة.

## 3. العقد المقترح

المسار:

`GET /api/v1/student/subject/training-center?subject_version_id={id}`

الاستجابة:

- `student_id`
- `subject_version_id`
- `generated_at`
- `identity.name`
- `identity.curriculum_label`
- `tools` بترتيب ثابت
- `version`

كل أداة تتضمن:

- `key`: مفتاح ثابت غير مترجم.
- `title`: اسم عربي.
- `description`: وصف مختصر.
- `activity_type`, `activity_mode`, `source` لعقد التجهيز.
- `available`, `status`, `reason`.
- `item_count`: رقم مؤكد أو `null`.

المفاتيح الثابتة:

- `choose`
- `truefalse`
- `connect`
- `fill`
- `speed`
- `smart_review`

## 4. قرارات عدم الاختلاق

- لا يعاد عدد أسئلة إذا تعذر إثبات جدول النوع وعلاقته بالمادة.
- لا تعتبر مراجعة الأخطاء متاحة لمجرد وجود أسئلة؛ يجب وجود أخطاء مؤكدة للطالب.
- لا يبدأ المركز جلسة ولا يخصم قلبًا.
- لا يمرر Android رصيدًا أو أهلية كمصدر حقيقة.
- لا ينشأ endpoint منفصل لكل أداة.
- لا يضاف SQL أو migration في هذه الدفعة ما لم يثبت نقص لا يمكن تجاوزه.

## 5. خطة التنفيذ

1. إضافة عقد OpenAPI وFixture واختبار PHP لمسار المركز.
2. إضافة DTO/API داخل `core-network` وتوصيله عبر `MasaryNetwork`.
3. إنشاء وحدة `feature-training-center` بنماذج وRepository وCache وViewModel وواجهة RTL.
4. توسيع عقد شاشة التجهيز بمفتاح أداة ثابت ومتوافق.
5. ربط صفحة المادة بالمركز، وربط الأداة المتاحة بشاشة التجهيز.
6. تشغيل Android CI وHostinger API ثم مراجعة الفرق والحالات الطرفية.

## 6. الحدود المحفوظة

- لا نشر إلى Hostinger.
- لا SQL أو migrations على الإنتاج.
- لا تعديل قاعدة بيانات الإنتاج.
- لا تعديل Push V2 أو PWA أو service worker.
- لا تحميل أسئلة أو إجابات في مركز التدريب.
- لا بناء واجهات حل الاختبارات أو النتائج قبل مراحلهما.
