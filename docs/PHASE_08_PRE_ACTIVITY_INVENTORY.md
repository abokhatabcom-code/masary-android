# المرحلة الثامنة — شاشة التجهيز قبل النشاط التعليمي

## الحالة والنطاق

هذا المستند يصف التنفيذ الموجود في فرع:

`phase-08-pre-activity-implementation`

والمعروض داخل Draft Pull Request #46 إلى:

`official/phase-08-pre-activity-preparation`

لم يتم النشر إلى Hostinger، ولم يُشغّل أي SQL أو Migration على الإنتاج، ولم يُعدّل Push V2 أو PWA أو `service worker`.

## الهدف المثبت

كل نقطة بدء تعليمية مرتبطة في تطبيق الطالب تمر أولًا عبر شاشة تجهيز Native موحدة. فتح الشاشة عملية قراءة فقط؛ لا ينشئ محاولة، ولا يخصم قلبًا أو جوهرة، ولا ينشئ جلسة. الكتابة تبدأ فقط عند ضغط «ابدأ النشاط» وبعد تحقق الخادم من الطلب.

## الجرد قبل التنفيذ

### Android

- الصفحة الرئيسية والتنقل typed كانا موجودين من المرحلة السابعة.
- خطوة الموجّه كانت تحمل معرف المادة والوحدة و`action_key` لكنها لم تمر بمحرك تجهيز مستقل.
- لم يكن هناك مخزن موحد لمفتاح `Idempotency-Key` أو حالة نتيجة البدء غير المعروفة.
- واجهات الأسئلة الخمسة ليست منفذة بعد، لذلك لا يجوز لشاشة التجهيز ادعاء فتحها.

### الخادم

- توجد مصادر حقيقية للطالب والمواد والقلوب والجواهر والموجّه.
- سجل محاولات اختبار الوحدة وفتح الوحدات والدروس النهائي تابع لمحركات المراحل اللاحقة، وليس مصدرًا مكتملاً في Adapter Android الحالي.
- لم يكن هناك جدول مستقل لجلسات نشاط Android أو عقد موحد للمعاينة والبدء.

## العقد المنفذ

### معاينة التجهيز

`POST /api/v1/student/activity/preview`

تعيد العملية:

- المادة والوحدة أو الدرس ونوع النشاط.
- الأهلية والسبب ورمز السبب.
- حالة الاشتراك بصيغة صريحة غير حاجبة في هذه المرحلة.
- القلوب والجواهر والتكلفة.
- حالة المحاولات مع `available/reason` عند غياب المصدر المؤكد.
- عدد الأسئلة والمدة عند توفر مصدرهما.
- جلسة سابقة قابلة للاستئناف.
- `version` و`generated_at`.

المعاينة لا تعدل جدول الجلسات ولا الأرصدة.

### إنشاء جلسة النشاط

`POST /api/v1/student/activity/start`

- يتطلب `Idempotency-Key` صالحًا.
- يستخرج الطالب من Bearer session فقط.
- يتحقق من الطلب وخطوة الموجّه من البيانات الخادمية.
- ينفذ التحقق وإنشاء الجلسة ضمن معاملة واحدة.
- يستخدم قفلًا خادميًا لنفس الطالب وبصمة النشاط، لمنع جلستين فعالتين حتى عند وصول مفتاحين مختلفين بالتزامن.
- يعيد الجلسة نفسها عند تكرار المفتاح والطلب نفسيهما.
- يرفض المفتاح نفسه عند استخدامه مع طلب مختلف.
- لا يطبق خصمًا غير معتمد؛ حقول الخصم تبقى صفرًا حتى يربطها المحرك المختص.
- يضمن rollback وتحرير القفل عند الاستثناء أو الإنهاء المبكر للطلب.

### حسم نتيجة البدء غير المؤكدة

`GET /api/v1/student/activity/start-status`

يستعلم التطبيق بالمفتاح الأصلي بعد انقطاع الشبكة. إذا لم توجد نتيجة، يعيد طلب البدء بالمفتاح نفسه بدل إنشاء مفتاح أو جلسة جديدة.

## سياسة الأهلية المؤكدة

نوع النشاط لا يؤخذ من Android كمصدر حقيقة. الخادم يقرأ `action_key` لخطوة الموجّه ويشتق منه النوع والوضع المتوقعين:

- خطوة تعلم عادية: `guide_step / learn`.
- معالجة الأخطاء أو المراجعة: `review / review`.
- اختبار السرعة: `speed_test / speed`.
- اختبار الوحدة: `unit_test / test`.

يجب أن يطابق طلب Android القيم المشتقة من خطوة الموجّه الخادمية، وأن تكون الخطوة غير مكتملة وتتبع المادة والوحدة نفسيهما.

اختبار الوحدة يظهر حاليًا غير متاح برمز `attempt_engine_pending`، لأن قاعدة الست محاولات يجب أن تأتي من محرك الاختبارات المؤكد لا من قيمة افتراضية. الأنشطة غير المطابقة لخطة الموجّه تظهر `invalid_guide_action` بدل السماح الوهمي.

## نموذج الجلسة

ملف المراجعة فقط:

`server-hostinger/database/20260724_api_activity_sessions.sql`

يتضمن:

- UUID عام غير قابل للتخمين.
- الطالب والمادة والوحدة والدرس.
- النوع والوضع والمصدر وخطوة الموجّه.
- الحالة وأوقات الإنشاء والانتهاء.
- Hash مفتاح منع التكرار وبصمة الطلب.
- JSON الطلب والنتيجة المؤكدة.
- حقول الخصم المرتبطة بالجلسة.
- قيدًا فريدًا لكل طالب ومفتاح منع تكرار.

تم تأجيل المفتاح الأجنبي إلى `app_users` حتى يُتحقق من نوع العمود في قاعدة الإنتاج. لم يُشغّل الملف على أي قاعدة بيانات.

## التنفيذ في Android

الوحدة الجديدة:

`feature-activity-preparation`

وتتضمن:

- وجهة تنقل typed ومحدودة القيم.
- طلبًا يتحقق محليًا من المعرفات والأنواع والمصادر.
- بصمة SHA-256 مستقرة للطلب.
- DTOs وRetrofit API داخل `core-network`.
- Repository يجدد Access Token عند الحاجة.
- ViewModel واحدًا لدورة المعاينة والبدء والاستعادة.
- DataStore صغيرًا لمفتاح البدء وبصمة الطلب.
- واجهة Compose عربية RTL بحالات: تحميل، جاهز، غير متاح، بدء، نتيجة غير معروفة، خطأ قابل للمحاولة، وانتهاء جلسة الدخول.
- تعطيل النقر المتكرر والانتقال مرة واحدة فقط بعد تأكيد الجلسة.
- عدم عرض معرف الجلسة أو تسجيله في الواجهة.

## الربط المنفذ

- زر خطوة الموجّه في الصفحة الرئيسية يفتح شاشة التجهيز.
- بعد نجاح إنشاء الجلسة ينتقل التطبيق إلى شاشة انتقالية آمنة، إلى أن تُبنى واجهات الأسئلة في مرحلتها.
- تسجيل الخروج يمسح حالة البدء المحلية المعلقة.
- التنقل الخارجي لا يتجاوز المصادقة أو شاشة التجهيز.
- تستطيع صفحات المواد اللاحقة إعادة استخدام العقد نفسه دون إنشاء محرك موازٍ.

## الاختبارات المضافة

### Android

- ثبات بصمة الطلب واختلافها باختلاف المحتوى.
- رفض المعرفات غير الصالحة قبل الشبكة.
- منع النقر المزدوج من إرسال طلبين.
- الاحتفاظ بالمفتاح نفسه عند نتيجة شبكة غير معروفة.
- الاستعلام عن الحالة ثم إعادة البدء بالمفتاح نفسه عند 404.
- استعادة جلسة مؤكدة قبل تحميل المعاينة.
- الانتقال إلى حالة انتهاء جلسة الدخول.
- مطابقة Fixtures مع DTOs.

### PHP

- المعاينة لا تنشئ جلسة.
- اشتقاق نوع نشاط الموجّه من `action_key` الخادمي.
- قبول خطوة التعلم والمراجعة المتطابقتين.
- حجب اختبار الوحدة حتى ربط المحاولات.
- تكرار المفتاح يعيد الجلسة نفسها.
- المفتاح نفسه مع طلب مختلف يعيد 409.
- مفتاحان مختلفان لا ينشئان جلستين فعالتين متطابقتين.
- الاستعلام عن نتيجة البدء.
- عدم حدوث خصم غير معتمد.
- منع نشاط يحتاج قلبًا عند الرصيد صفر.
- rollback الكامل عند فشل الإدراج.
- رفض خطوة موجّه غير صالحة.

## العناصر المؤجلة صراحة

- واجهات الأسئلة الخمسة.
- سجل المحاولات الفعلي وفتح اختبار الوحدة.
- قواعد فتح الوحدات والدروس خارج الموجّه.
- شاشة النتائج ومراجعة الأخطاء الكاملة.
- اقتصاد الجواهر ومركز القلوب الكاملان.
- عدد الأسئلة والمدة عندما لا يعيدهما المصدر الحالي.

تعود القيم المؤجلة بحالة صريحة أو `null`، ولا تُختلق أرقام أو أهلية.

## حدود الأمان

- لا ثقة في تكلفة أو رصيد أو محاولات قادمة من Android.
- لا اختيار لطالب من body أو query.
- لا تخزين لمفتاح منع التكرار الخام في قاعدة البيانات.
- لا تسجيل للتوكنات أو معرف الجلسة في الواجهة.
- لا Deep Link يتجاوز المصادقة وشاشة التجهيز.
- لا تعديل على Push V2 أو PWA أو `service worker`.

## بوابات الجودة

بوابتا Android CI وHostinger API تتوقفان حاليًا قبل تنفيذ أول خطوة، ولا تنتجان logs أو artifacts. أُعيد تشغيلهما وفشلتا بالطريقة نفسها. لذلك يبقى PR #46 في وضع Draft، ولا يصبح جاهزًا للدمج إلا بعد عودة التشغيل ونجاح:

1. مدقق OpenAPI والـFixtures.
2. فحص PHP syntax والاختبارات السلوكية.
3. اختبارات Android وLint.
4. بناء APKs الطالب والإدارة ونقطة البيع.
