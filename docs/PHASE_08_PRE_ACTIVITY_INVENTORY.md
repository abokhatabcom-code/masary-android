# جرد المرحلة الثامنة — شاشة التجهيز قبل النشاط التعليمي

## الحالة

هذا المستند هو خط الأساس التنفيذي للمرحلة الثامنة، ومصدره فرع:

`official/phase-08-pre-activity-preparation`

لا يتضمن هذا الجرد نشرًا إلى Hostinger، ولا تشغيل SQL أو migrations على الإنتاج، ولا أي تعديل على Push V2 أو PWA أو service worker.

## الهدف الوظيفي

كل نشاط تعليمي في تطبيق الطالب يجب أن يمر عبر شاشة تجهيز Native موحدة قبل فتح واجهة الأسئلة. شاشة التجهيز تقرأ حالة الطالب الحقيقية من الخادم، وتعرض الأهلية والتكلفة والمحاولات، ثم تنشئ جلسة خادمية واحدة فقط عند ضغط «ابدأ النشاط».

فتح شاشة التجهيز وحده عملية قراءة ولا يخصم قلبًا أو جوهرة ولا يسجل محاولة.

## الوضع الحالي في Android

- نقطة التطبيق الرئيسية موجودة في `app-student`.
- التنقل الداخلي للطالب أصبح typed داخل `feature-home` في المرحلة السابعة.
- وجهة خطوة الموجّه الحالية تحمل معرف المادة والوحدة ونوع الإجراء، لكنها تنتهي حاليًا عند واجهة مادة انتقالية ولا تمر بمحرك تجهيز مستقل.
- لا توجد حتى الآن وحدة Feature مستقلة مسؤولة عن دورة حياة تجهيز النشاط وإنشاء الجلسة.
- لا توجد حالة محفوظة موحدة لمفتاح `Idempotency-Key` الخاص بمحاولة البدء.
- واجهات الاختبارات الخمسة ليست ضمن نطاق هذه المرحلة؛ المطلوب تثبيت عقد الانتقال إليها بعد إنشاء جلسة صحيحة.

## الوضع الحالي في الخادم

- الخادم يملك منطقًا قائمًا للطالب والمادة والقلوب والجواهر والمحاولات وفتح المحتوى ضمن منصة الويب الحالية.
- يجب إعادة استخدام مصادر الحقيقة الحالية وعدم نسخ قواعدها داخل Android.
- يجب فحص مسارات بدء الاختبارات والمراجعة الحالية قبل اعتماد أسماء المسارات النهائية للـAPI.
- لا يجوز إنشاء مسار موازٍ إذا كان هناك مسار حالي يمكن تطويره بأمان.
- أي عملية كتابة جديدة يجب أن تعتمد Bearer session فقط لهوية الطالب، وأن تكون idempotent وداخل transaction.

## العقد المطلوب

### معاينة التجهيز

عملية قراءة فقط تعيد:

- المادة والوحدة أو الدرس ونوع النشاط.
- حالة الفتح والأهلية والاشتراك.
- القلوب والجواهر والتكلفة.
- المحاولات المستخدمة والمتبقية.
- عدد الأسئلة والمدة التقديرية عند توفرهما.
- جلسة سابقة قابلة للاستئناف.
- حالات `available/status/reason` عند غياب مصدر موثوق.

### إنشاء جلسة النشاط

عملية كتابة تتطلب `Idempotency-Key` وتعيد:

- معرف جلسة فريدًا غير قابل للتخمين.
- حالة الجلسة.
- وجهة النشاط التالية.
- نتيجة الخصم أو الحجز والرصيد بعد العملية.
- نفس النتيجة عند إعادة الطلب نفسه بالمفتاح نفسه.

## نموذج Android المقترح

إنشاء وحدة مستقلة مبدئيًا باسم:

`feature-activity-preparation`

وتتكون من:

- `ActivityPreparationDestination`
- `ActivityPreparationRepository`
- DTOs داخل `core-network`
- `ActivityPreparationViewModel`
- `ActivityPreparationScreen`
- مخزن محلي صغير لحالة عملية البدء غير المحسومة
- اختبارات ViewModel والتنقل ومنع النقر المكرر

## قواعد منع التكرار

- إنشاء مفتاح واحد لكل نية بدء فعلية.
- الاحتفاظ بالمفتاح عبر دوران الشاشة وإعادة تركيب Compose.
- تعطيل النقر المتكرر أثناء الطلب.
- عند انقطاع الشبكة بعد إرسال الطلب لا يُنشأ مفتاح جديد؛ يعاد الاستعلام أو الطلب بالمفتاح نفسه.
- الانتقال إلى النشاط مرة واحدة فقط بعد استلام جلسة مؤكدة.

## نقاط الربط في المرحلة الحالية

1. زر خطوة الموجّه في الصفحة الرئيسية.
2. نقاط بدء النشاط التي ستظهر داخل المواد.
3. أي مسار قائم لبدء اختبار أو مراجعة بعد التحقق من مصدره.

## عناصر مؤجلة

- واجهات الأسئلة الخمسة الكاملة.
- شاشة النتائج والمراجعة التفصيلية.
- اقتصاد الجواهر الكامل.
- مركز القلوب الكامل.
- تفاصيل المحاولات داخل صفحة المادة.

هذه العناصر لا تمنع إنشاء جلسة صحيحة أو تثبيت عقد الانتقال إليها.

## اختبارات القبول الأولية

- المعاينة لا تعدل أي رصيد أو محاولة.
- النقر المزدوج ينتج جلسة واحدة.
- تكرار المفتاح نفسه يعيد الجلسة نفسها.
- تعارض المفتاح يعيد 409.
- لا يمكن بدء محتوى غير تابع للطالب أو مقفل.
- فشل transaction لا يترك خصمًا أو جلسة جزئية.
- Android لا ينتقل قبل تأكيد الجلسة.
- انتهاء الجلسة يعيد الطالب إلى المصادقة بأمان.

## حدود الأمان

- لا ثقة في القيم القادمة من Android مثل التكلفة أو الرصيد أو عدد المحاولات.
- لا اختيار لطالب من query أو body.
- لا تسجيل للتوكنات أو بيانات حساسة.
- لا Deep Link يتجاوز المصادقة وشاشة التجهيز.
- لا تعديل على Push V2 أو PWA أو service worker.

## الخطوة التنفيذية التالية

فحص ملفات بدء الاختبار والمراجعة الحالية في Android والخادم وعقد OpenAPI، ثم تثبيت أسماء المسارات والـDTOs ونموذج الجلسة قبل كتابة واجهة الشاشة.
