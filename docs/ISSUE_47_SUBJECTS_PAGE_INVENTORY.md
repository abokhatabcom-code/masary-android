# جرد المرحلة التاسعة — صفحة المواد الدراسية

**المهمة:** GitHub Issue #47  
**فرع التنفيذ:** `phase-09-subjects-implementation`  
**نقطة الأساس:** `533b3410c2edd44f5c30e67eb22f86e3eaa2aaf3`  
**تاريخ الجرد:** 2026-08-02

## الملخص التنفيذي

توجد حاليًا معاينة مواد داخل `Home Snapshot` وتبويب باسم «المواد»، لكنها ليست صفحة مواد مستقلة. التبويب يعيد استخدام بيانات الصفحة الرئيسية المخزنة، ولا يملك API أو Repository أو ViewModel أو Cache أو حالات تحديث مستقلة.

المصدر الخادمي الحالي أفضل نقطة لإعادة الاستخدام، لكنه محدود لاحتياج الصفحة الرئيسية: يعيد بحد أقصى 12 مادة، ويحتوي فقط على معرف نسخة المادة والاسم والقلوب، بينما `progress_percent` يظل `null` عمدًا لغياب مصدر مؤكد. لا توجد حاليًا حقول مؤكدة لمفتاح الوسائط، اسم نسخة المنهج، حالة الوصول التفصيلية، أو آخر نشاط لكل مادة داخل القائمة.

بناء المرحلة التاسعة يجب أن يوسّع القراءة الحالية دون إنشاء منطق موازٍ لربط الطالب بمنهجه، وأن يبقي الحقول غير المؤكدة بحالة صريحة بدل اختراع قيم.

## 1. الوضع الحالي في الخادم

### 1.1 مصدر المواد المعتمد حاليًا

الملف:

`server-hostinger/public_html/api/_student_home_subjects.php`

الدالة:

`api_student_home_curriculum_subjects(PDO $pdo, int $studentId)`

السلوك الحالي:

- تقرأ `grade_id` و`city_id` من `app_users`.
- تقرأ `curriculum_id` من `cities`.
- تختار `subject_versions` المطابقة للصف والمنهج.
- تتحقق اختياريًا من `is_active` عندما يكون العمود موجودًا.
- ترتب حسب أول مصدر مؤكد متاح من:
  - `subject_versions.sort_order`
  - `subjects.sort_order`
  - `subjects.display_order`
  - ثم الاسم والمعرف كخيار أخير.
- تربط `student_subject_state` لاستخراج القلوب عند وجود سجل، مع fallback يساوي 3.
- تحد القائمة إلى 12 مادة لأنها صُممت لمعاينة الصفحة الرئيسية.
- عند غياب بنية الربط الحديثة أو حدوث خطأ، ترجع إلى `api_student_home_subjects()` المبنية على `student_subject_state`.

الحقول المعادة حاليًا:

- `subject_version_id`
- `name`
- `hearts`
- `progress_percent = null`

### 1.2 القيود المؤكدة في المصدر الحالي

- الربط الحديث يتحقق من الصف ومنهج المدينة، لكنه لا يطبق فلتر قسم/شعبة في هذه الدالة.
- لا يعيد اسم الصف أو المدينة أو المنهج.
- لا يعيد `media_key` أو صورة.
- لا يعيد حالة وصول مؤكدة لكل مادة.
- لا يعيد آخر نشاط لكل مادة.
- لا يوجد مصدر تقدم مؤكد مستخدم في هذا المسار، لذلك القيمة `null` صحيحة ولا يجوز استبدالها بنسبة تقديرية.
- الحد 12 مناسب لـHome Preview لكنه ليس عقدًا مناسبًا لصفحة «عرض الكل».

### 1.3 Home endpoint

الملف:

`server-hostinger/public_html/api/v1/student/home.php`

- يصادق الطالب من Bearer token.
- يطبق rate limit خاصًا بالصفحة الرئيسية.
- يستبدل قسم `subjects` في Home payload بنتيجة `api_student_home_curriculum_subjects()`.
- يضمّن قائمة المواد في بصمة `version` الخاصة بالـHome Snapshot.

هذا يعني أن منطق اختيار المواد موجود بالفعل ويجب إعادة استخدامه، لكن لا ينبغي تحميل Home Snapshot كاملًا لتحديث صفحة المواد المستقلة.

### 1.4 آخر نشاط

يوجد مصدر مستخدم في Home داخل:

`api_student_home_continue()`

ويقرأ من `student_last_activity` بيانات مادة/وحدة واحدة للمتابعة العامة. هذا يثبت وجود مصدر محتمل، لكنه لا يثبت بعد أن الجدول يحتفظ بسجل صالح لكل مادة. يجب فحص بنيته واستخدام استعلام مجمع فقط إذا كان يدعم ذلك؛ وإلا يعود `last_activity.available=false`.

## 2. الوضع الحالي في Android

### 2.1 عقد الشبكة

الملف:

`core-network/src/main/java/app/masary/core/network/home/StudentHomeApi.kt`

`HomeSubjectDto` يحتوي فقط على:

- `subjectVersionId`
- `name`
- `hearts`
- `progressPercent`

ولا توجد `StudentSubjectsApi` مستقلة.

### 2.2 التنقل

الملف:

`feature-home/src/main/java/app/masary/feature/home/ui/StudentDestinations.kt`

الموجود حاليًا:

- `StudentDestination.Subjects`
- `StudentDestination.SubjectDetails(subjectVersionId, unitId, actionKey)`

العقد typed موجود وقابل لإعادة الاستخدام، لكن تعريفه داخلي داخل `feature-home`. الضغط من قائمة المواد يمرر `subjectVersionId` فقط، بينما `unitId/actionKey` مستخدمان لمسار الموجّه.

### 2.3 واجهة تبويب المواد الحالية

الملف:

`feature-home/src/main/java/app/masary/feature/home/ui/StudentHomeScreen.kt`

السلوك الحالي:

- تبويب المواد يستخدم `currentData.subjects` من Home Snapshot.
- لا يوجد ViewModel مستقل للمواد.
- لا يوجد تحميل أو تحديث أو خطأ مستقل للمواد.
- لا يوجد Pull-to-refresh داخل تبويب المواد.
- البطاقة تعرض الاسم والقلوب فقط.
- صفحة تفاصيل المادة الحالية مؤقتة، وتعرض اسم المادة ورسالة أن الوجهة جاهزة أو أن المحتوى قادم لاحقًا.

### 2.4 Cache الحالي

الملف:

`feature-home/src/main/java/app/masary/feature/home/data/DataStoreHomeSnapshotStore.kt`

- Home Snapshot مخزن في DataStore منفصل.
- مربوط بمعرف الطالب.
- له schema version واضح.
- صلاحيته الحالية 24 ساعة.
- يتحقق من تطابق هوية الطالب قبل العرض.
- مسح Home Snapshot يحدث عند تسجيل الخروج.

يمكن إعادة استخدام النمط نفسه لصفحة المواد، لكن بمخزن ومفاتيح مستقلة حتى لا يؤدي تلف أو تحديث قائمة المواد إلى إتلاف Cache الصفحة الرئيسية.

## 3. الفجوات المطلوب إغلاقها في المرحلة التاسعة

1. لا يوجد endpoint مستقل خفيف لقائمة المواد الكاملة.
2. لا توجد وحدة `feature-subjects`.
3. لا يوجد Repository أو ViewModel أو UiState مستقلة.
4. لا يوجد Cache مستقل وقابل للتحقق من مالك البيانات.
5. تبويب المواد لا يحدث نفسه ولا يملك حالات Offline مستقلة.
6. القائمة الحالية محدودة بـ12 عنصرًا.
7. لا يوجد سياق أكاديمي معروض للطالب.
8. لا توجد حالة صريحة للتقدم غير المتاح؛ `null` يصل حاليًا دون تفسير.
9. لا توجد حالة صريحة لمفتاح الوسائط أو الوصول أو آخر النشاط عند غياب المصدر.
10. فلتر القسم/الشعبة غير مثبت في دالة المواد الحالية ويجب عدم الادعاء بأنه مطبق قبل التحقق من schema والقواعد القديمة.
11. صفحة تفاصيل المادة ليست ضمن هذه المرحلة ويجب ألا تتحول إلى واجهة وهمية تبدو مكتملة.

## 4. خطة التوافق المعتمدة

### الخادم

- إضافة `GET /api/v1/student/subjects` كـAdapter قراءة فقط.
- إعادة استخدام منطق `api_student_home_curriculum_subjects` بعد جعله يدعم حدًا مناسبًا للـHome وقائمة كاملة للمواد، أو استخراج query builder مشترك.
- إبقاء Home Preview محدودة دون تغيير شكلها الخلفي.
- إعادة حقول اختيارية على هيئة كائنات ذات `available/status/reason` بدل قيم مضللة.
- استخراج الطالب من Bearer session فقط.
- عدم قبول `user_id` أو الصف أو المنهج من العميل.
- فحص القسم/الشعبة من schema والمنطق القديم قبل إضافته للفلترة.
- جلب آخر الأنشطة باستعلام مجمع واحد فقط إذا كان مصدر البيانات يسمح.
- عدم إنشاء جدول أو migration لهذه الصفحة.

### Android

- إنشاء وحدة `feature-subjects` مستقلة.
- إنشاء DTO/API في `core-network`.
- إنشاء Repository يدعم refresh token بنفس سياسة Home.
- إنشاء DataStore Snapshot مستقل ومملوك لمعرف الطالب.
- إنشاء ViewModel بحالات: Loading، Content، Error، SessionExpired، مع Cache-first وbackground refresh.
- ربط تبويب المواد وزر «عرض الكل» بالمسار نفسه.
- إبقاء اختيار المادة عبر معرف `subject_version_id` موجب فقط.
- عدم بناء الوحدات أو الدروس أو الاختبارات أو صفحة المادة الكاملة.

## 5. الحقول وحالة مصدر الحقيقة

| الحقل | الحالة الحالية | قرار المرحلة |
|---|---|---|
| معرف نسخة المادة | مؤكد | مطلوب |
| اسم المادة | مؤكد | مطلوب |
| ترتيب الإدارة | مؤكد شرطيًا حسب أعمدة schema | الحفاظ على ترتيب الخادم |
| القلوب | موجود من state/fallback | اختياري، وليس أساس ترتيب أو وصول |
| نسبة التقدم | غير مؤكدة | `available=false`, `percent=null` حتى العثور على مصدر حقيقي |
| اسم نسخة المنهج | غير معاد حاليًا | يضاف فقط من مصدر مؤكد |
| الصف/المدينة/القسم | غير معادة حاليًا | تضاف كسياق اختياري من مصدر مؤكد |
| مفتاح الوسائط | غير مؤكد | `available=false`, واستخدام fallback محلي آمن |
| حالة الوصول | غير مؤكدة لكل مادة | حالة صريحة غير متاحة حتى ربط سياسة موثوقة |
| آخر نشاط لكل مادة | مصدر محتمل غير مثبت | استعلام مجمع إن أمكن، وإلا غير متاح |

## 6. ما لن يتغير

- لا تغيير على Push V2 أو PWA أو service worker.
- لا نشر إلى Hostinger.
- لا تشغيل SQL أو تعديل قاعدة الإنتاج.
- لا تغيير لخوارزمية الموجّه.
- لا إعادة كتابة قواعد القلوب أو الجواهر أو الاشتراك داخل Android.
- لا دمج في `main` أو فرع المرحلة قبل نجاح الجودة واعتماد المالك.
